# hack5250: Guardrailed IBM i (AS/400) Application Pen Testing

Designed for **authorised** penetration testing of a scoped 5250 application
on IBM i. Constrains scope, limits aggression, and requires human approval
before escalation. All datastream traffic is automatically logged to SQLite by
the proxy for full traceability. This is the **5250 sibling of
`skills/hack3270.md`** — same discipline, different protocol and platform.

## Prerequisites

1. hack5250 proxy running: `python hack5250.py <ibmi_ip> 23 -n <project>`
2. A tn5250 emulator (IBM i ACS, tn5250j, Mocha) connected to `127.0.0.1:5251`
3. The hack5250 MCP server registered (root `.mcp.json` does this)
4. Read `README.md` once — it explains *why* the FFW attacks are selective

## The IBM i Trust Model

IBM i security is **object-based**, not transaction-based like CICS. Every
object (program, file, command, device) carries an authority list. User
profiles carry *special authorities* (`*ALLOBJ`, `*SECADM`, `*JOBCTL`,
`*SPLCTL`, `*SERVICE`, `*AUDIT`, `*IOSYSCFG`, `*SAVSYS`). Most production
business apps confine users with **menu security**: the user profile has
`INLPGM`/`INLMNU` set to the application's entry menu and `LMTCPB(*YES)` so
the user cannot type CL commands. The 5250 display file (DDS) then enforces
which fields are protected, hidden, or numeric.

The application's security therefore rests on **three assumptions** that
hack5250 attacks:

| Assumption | Reality | hack5250 attack |
|---|---|---|
| The terminal enforces field protection (DDS `DSPATR(PR)`). | It's a Field-Format-Word bit in the format table. | `enable_ffw_unprotect`, `send_field`/`send_fields` with SBA at protected positions. |
| The terminal hides what `DSPATR(ND)` says to hide. | It's screen-attribute byte `0x27`. | `enable_ffw_reveal_hidden`. |
| The terminal sends only the AID keys the SOH PF-mask allows. | The mask is advisory; the host's `EXFMT` still receives the AID. | `get_pf_key_mask`, `send_masked_keys`. |
| `LMTCPB(*YES)` prevents CL command access. | Only on the *intended* command line. ATTN → Operational Assistant → F9 is a different command line. | `attempt_attn_escape`. |
| Telnet auto-signon encrypts the password. | RFC 2877 §5: *the client decides* whether to encrypt, based on whether it received a server seed. | `enable_ibmrseed_downgrade`. |
| Device names identify the workstation. | `DEVNAME` is a NEW-ENVIRON USERVAR the client supplies. | `spoof_device_name`. |

Unlike 3270/CICS where the equivalent of "out" is TSO, on IBM i the
equivalent is a **CL command line** (`===>`). Reaching it from inside a
menu-confined application is the headline finding.

## Scope Definition

### Program-prefix locking

IBM i applications are *program*-based. The display file's row-2 header
typically shows the running program name (`MCMM`, `MCOR`, `MCAD`). Extract
the **common prefix** and lock testing to it.

- **In scope:** any screen whose row-2 program name matches the prefix; any
  menu option that navigates within that prefix.
- **Out of scope by default:** IBM-supplied menus (`MAIN`, `ASSIST`, `CMDxxx`,
  `GO USRSEC`, `GO SECTOOLS`), the QDSIGNON sign-on screen, System Service
  Tools (SST/DST), QSHELL/PASE, and any program outside the prefix.

### What is in scope

- Every screen reachable via in-prefix programs.
- All input/protected/hidden fields on those screens.
- AID keys, ATTN, System-Request behaviour from those screens.
- Protected-field tampering on those screens.
- In-application authentication (supervisor PINs, app-level passwords).
- Proving CL-escape via ATTN — run **one** read-only command, return.

### What is out of scope

- The sign-on screen (QDSIGNON) credential brute force.
- CL post-exploitation: `WRKOBJ`, `CHGUSRPRF`, `SBMJOB`, `STRSQL`,
  `CRTUSRPRF`, `SAVLIB`, `RSTOBJ`, `ENDSBS`, `PWRDWNSYS`.
- Object-authority enumeration outside the application's library.
- SST/DST.

## Hard Guardrails

### 1. No system CL command execution

If you reach a `===>` prompt (via ATTN escape or otherwise), prove it with
**exactly one read-only command** — `DSPJOB` — capture the output, then
return (`F12` or `F3`). Do NOT run `WRKACTJOB`, `WRKSYSSTS`, `DSPUSRPRF`,
`CHGxxx`, `DLTxxx`, `SBMJOB`, `ENDxxx`, `PWRDWNSYS`, `STRSQL`, or any command
that modifies state. The `===>` prompt + `DSPJOB` output is sufficient proof.

### 2. No QDSIGNON brute force

IBM i enforces profile lockout via system value `QMAXSIGN` (typically 3–5)
and the action via `QMAXSGNACN` (disable profile, disable device, or both).
**Never** brute-force the sign-on screen. Locking a profile affects the real
user. The RFC 4777 username oracle (`preauth.py`) is the *only* permitted
sign-on probe — see Guardrail 6.

### 3. Stop on RPG/COBOL runtime error — never repeat

The IBM i equivalents of a CICS abend are message IDs:

- `MCHxxxx` — machine-check (pointer/decimal-data/divide-by-zero)
- `RNQxxxx` / `RNXxxxx` — RPG runtime inquiry/escape
- `CPF5xxx` — display-file errors (e.g. `CPF5068` from RRN=0)
- `CEExxxx` — ILE condition

If `get_screen_text` shows one, or `IBMiMessageDetector` reports one:
document the exact payload, **stop that line of testing**, never resend it.

### 4. No job submission

Never `SBMJOB`, never write to an outq for execution, never `STRPCCMD`
toward the operator's PC.

### 5. IBMRSEED downgrade and DEVNAME spoof require human approval

`enable_ibmrseed_downgrade` causes the *operator's real password* to traverse
the wire in cleartext and be captured. `spoof_device_name` may auto-sign-on
as a privileged profile. Both are valid tests but escalate beyond
"application" scope into "platform/credential" scope. Ask first.

### 6. Honour the RFC 4777 lockout-warning code

The username oracle (Startup Response after `IBMSENDCONFREC=YES`) returns:

| Code (EBCDIC) | Meaning | Action |
|---|---|---|
| `F0F0F0F0` | Success | — |
| `F0F0F0F2` | User not found | Safe to continue enumerating. |
| `F0F0F0F4` | Bad password | User exists. **Do not retry passwords for this user.** |
| `F0F0F0F8` | Next bad password disables profile | **STOP for this user immediately.** |
| `F0F0F0F6` / others | See RFC 4777 §5 | Log and move on. |

The host *tells you* before lockout. Never send the attempt that would trip
`QMAXSIGN`.

### 7. No special-authority operations

Even if a CL escape lands you in a profile with `*ALLOBJ`/`*SECADM`, do not
exercise those authorities. Document the profile name and authorities
(`DSPJOB` shows the current user) and return.

### 8. Selective unprotect only

`enable_ffw_unprotect` is implemented selectively (hidden fields only) for a
reason — clearing BYPASS on every protected field breaks the format-table
contract and the host rejects the inbound. Do not attempt to widen it via
`send_raw_hex`.

### 9. Sensitive data handling

Same as hack3270 Guardrail 8. Mask PII, account numbers, payment data in all
reports and chat output.

## Escalation Protocol

Ask the human and wait for confirmation before:

- `enable_ibmrseed_downgrade` / `get_captured_credentials`
- `spoof_device_name`
- USERVAR injection (`IBMPROGRAM`/`IBMIMENU`/`IBMCURLIB` rewrite)
- Any CL command beyond `DSPJOB` after an escape
- `inject_wordlist` with `cl-commands.txt` against a live input field
- Out-of-prefix program calls
- Resuming after an `MCH`/`RNQ`/`RNX`/`CPF` error
- Subfile RRN tampering with destructive options (4=Delete)

State **what / why / risk level** when asking.

## Safe Pen Test Methodology

### Phase 1 — Reconnaissance (read-only)

**Step 1. Connect and identify scope.**
`ping` → `quick_recon`. Read the row-2 program name from `get_screen_text`;
extract the prefix. State "Scope locked to prefix XX" to the human.

**Step 2. Baseline.**
Navigate 3–5 menu options normally (`select_menu_option`). Record response
times and the `log_count` delta per round-trip.

**Step 3. Map the menu tree.**
For each option on each menu: `select_menu_option(n)` → `get_screen_text` →
record (program name, title, input-field coords) → `send_aid("F12")` to
return. Build the full tree before any active testing.

**Step 4. Field census per screen.**
On each screen: `get_screen_fields()`. Record every
`{row, col, length, protected, hidden, numeric}` tuple. Note hidden+protected
fields — those are the tampering targets.

**Step 5. PF-mask census.**
On each screen: `get_pf_key_mask()`. Record `masked_keys` — the F-keys the
host claims are invalid. These are fuzz priority later.

### Phase 2 — Passive reveal

**Step 6. Reveal hidden fields.**
`enable_ffw_reveal_hidden` (and `enable_ffw_high_visibility`). Re-walk every
mapped screen. Compare `get_screen_text` before/after. Anything newly
visible is a finding candidate: hidden menu options (`DSPATR(ND)` as access
control), hidden flags (`Purchaseable: Y`), session state.

**Step 7. PUTOVR / protect-flip differential.**
With the `differential.py` detectors armed, navigate the same path twice.
A field that flips protected→input across `EXFMT`s is driven by an RPG
indicator — that flip *is* the authorisation decision. Map which prior input
caused it.

### Phase 3 — Active testing

**Step 8. Masked-key fuzzing.**
On each screen, `send_masked_keys()` then `get_screen_text`. A masked key
that *does something* is a forgotten handler. Document it.

**Step 9. ATTN escape.**
`attempt_attn_escape()` from the application's main menu and from at least
one deep screen. Classify the result:
- `CMDLINE` — **Critical.** Run `DSPJOB` once. Record current-user and
  job name. `F12` back. Report.
- `OPER_ASSIST` — Operational Assistant reached but F9 blocked. **High.**
- `SYS_REQUEST` — System-Request menu. Try option 1 (alternate sign-on)
  observation only — do not sign on.
- `BLOCKED` — `ATNPGM` overridden. Positive control; document.

**Step 10. Protected-field tampering.**
For each hidden+protected field that looks business-relevant (price, status,
quantity, item-number, RRN), report to the human first. If approved, use
`tamper_protected_field(row, col, value, legit_input_row, legit_input_col,
legit_input_value)` — the combined legit-input + extra-SBA packet. After
sending, navigate forward and check whether the tampered value persisted
(the price-tamper finding requires seeing it in *the next screen* or order
history, not just the echo).

**Step 11. CA-AID + RTNCSRLOC + subfile RRN (with approval).**
These three (`ca_key.py`) are surgical:
- **CA-AID + data:** find an `Fnn` key that behaves like a CA key (sends no
  data normally). Send it *with* data via `send_fields(..., aid="Fnn")`.
  If RPG branches on `*INKx` and skips re-validation, tampered data lands.
- **RTNCSRLOC spoof:** put the inbound cursor on a *protected* field's
  coords. If the program branches on cursor-field-name, it acts on a field
  the user couldn't have selected.
- **Subfile RRN:** find the hidden 4-digit zoned field that increments after
  ROLLUP. Tamper it so option N applies to a different record. **Do not use
  option 4 (Delete) without approval.** RRN=0 will `CPF5068`.

**Step 12. In-app credential brute force (with approval).**
For app-level PIN/supervisor fields: `arm_mask_capture` → type `****` in the
field in the emulator → `get_mask_status` → `inject_wordlist` with a numeric
list, or use `FieldBruter`. Stop on first hash-differential hit.

### Phase 2A — Source-informed (if application source is available)

Same model as hack3270's Phase 2A, but the source artefacts are IBM i:

| Artefact | Source type | Look for |
|---|---|---|
| Display file (DDS) | `DSPF` | `DSPATR(ND)` / `DSPATR(PR)` conditioned on indicators; `CAnn`/`CFnn` keywords (CA = no data, CF = data); `RTNCSRLOC`; `SFLRCDNBR`; `PUTOVR`/`OVRDTA` |
| RPG program | `RPGLE`/`SQLRPGLE` | `EXFMT` without re-validate; `*INKx` branches that skip checks; `READC`/`UPDATE` using untrusted RRN; embedded `EXEC SQL` with string concat; `USRPRF(*OWNER)` in the H-spec (adopted authority) |
| CL program | `CLP`/`CLLE` | `CHGJOB`, `OVRDBF`, library-list changes; `MONMSG` that swallows errors |
| Service program | `SRVPGM` | Exported procedures callable directly |

A DDS `CAnn` keyword + an RPG `*INKx` branch with no re-validate is a
source-confirmed CA-AID-tampering finding before you send a packet.

### Phase 4 — Reporting

Same template as hack3270 (below), with `MCH/RNQ/CPF` codes in place of
abend codes and program names in place of transaction codes.

## Recovery Procedures

| Situation | Action |
|---|---|
| Reached `===>` (intentional) | `DSPJOB` once → screenshot/capture → `F12` until back in app. |
| Reached `===>` (accidental) | Do NOT type anything. `F12` / `F3` back. |
| Operational Assistant menu | `F12`. |
| System Request menu | `ENTER` on a blank option line, or `F12`. |
| `Display Program Messages` panel | Read message IDs, then `ENTER` to continue. |
| `MCH`/`RNQ` inquiry message ("C G D F") | Reply `C` (cancel). Record the payload. Do not retry. |
| Screen frozen / X-SYSTEM | Wait 10s. `RESET` (Ctrl) in the emulator. If still locked, report — do NOT spam keys. |
| Format-table reject (`CPF5192`/`CPF5068`) | `disable_all_ffw_hacks`; navigate `F12` then back in. |
| Signed off (`CPF1120`, sign-on screen) | **STOP.** Report. Do not attempt re-signon without approval. |
| `STRPCCMD` alert from `detector.py` | The host tried to run a command on the operator PC. **High** finding; defensive — do not relay it. |

## Technical Reference

### 5250 inbound packet (client → host)

```
+------------------------+----------+--------+-------+-----+--------------------+
| 10-byte tn5250 header  | cursor   |  AID   | [SBA  row col  EBCDIC data] ...  |
|  len(2) 12A0 ... opcode|  row col |  1 byte|            repeated              |
+------------------------+----------+--------+----------------------------------+
```

`send_field`/`send_fields` build this for you. `send_raw_hex` is the escape
hatch.

### Screen-attribute bytes (host → client, in WTD)

| Byte | Display | Typical DDS source |
|---|---|---|
| `0x20` | Green | default |
| `0x21` | Green reverse | `DSPATR(RI)` |
| `0x22` | White | `DSPATR(HI)` |
| `0x24` | Green underline | `DSPATR(UL)` |
| `0x27` | **Non-display** | `DSPATR(ND)` — the reveal target |
| `0x28` | Red | `COLOR(RED)` |
| `0x3A` | Blue | `COLOR(BLU)` |

### FFW (Field Format Word) bits

| Bit | Meaning | hack5250 toggle |
|---|---|---|
| `0x4000` | FFW marker (always set) | — |
| `0x2000` | **BYPASS** — cursor cannot enter | `enable_ffw_unprotect` clears it (hidden fields only) |
| `0x1000` | DUP enable | — |
| `0x0800` | Modified-data-tag | — |
| `0x0700` | Shift/edit (numeric, alpha-only, etc.) | `enable_ffw_remove_numeric` clears |
| `0x0008` | Mandatory-entry | `enable_ffw_remove_numeric` clears |
| `0x0007` | Field-exit / right-adjust | `enable_ffw_remove_numeric` clears |

### AID codes (5250 — **not** the same as 3270)

| Key | Byte | Key | Byte |
|---|---|---|---|
| F1–F24 | `0x31`–`0x3C`, `0xB1`–`0xBC` | ENTER | `0xF1` |
| ROLLUP (PgDn) | `0xF5` | ROLLDN (PgUp) | `0xF4` |
| HELP | `0xF3` | PRINT | `0xF6` |
| CLEAR | `0xBD` | RECBS | `0xF8` |
| PA1–PA3 | `0x6C`, `0x6E`, `0x6B` | AUTO | `0x3F` |

`ATTN` and `SYSREQ` are **header flag bits**, not AID bytes — use
`send_attn`, not `send_aid`.

### Message-ID prefixes

| Prefix | Source | Severity guide |
|---|---|---|
| `CPF` | OS/400 — most common | Varies; `CPF9898` is generic app error |
| `CPD` | Diagnostic | Low |
| `CPI` | Informational | Info |
| `MCH` | Machine interface — pointer/decimal/arith | **Stop** (Guardrail 3) |
| `RNQ` / `RNX` | RPG runtime | **Stop** (Guardrail 3) |
| `CEE` | ILE condition | Usually stop |
| `SQL` | DB2 for i | Note for SQLi findings |

### Relevant system values (do not change — report only)

`QSECURITY` (10/20/30/40/50), `QMAXSIGN`, `QMAXSGNACN`, `QPWDLVL`,
`QLMTDEVSSN`, `QINACTITV`, `QALWOBJRST`, `QRMTSIGN` (controls auto-signon —
the DEVNAME-spoof prerequisite).

## Tool Quick Reference

**Recon:** `ping`, `quick_recon`, `get_screen_text`, `get_screen_fields`,
`get_pf_key_mask`, `log_count`, `get_ffw_status`, `get_negotiation_status`

**FFW manipulation:** `enable_ffw_reveal_hidden` / `…_unprotect` /
`…_remove_numeric` / `…_high_visibility` (+ `disable_*`),
`enable_all_ffw_hacks`, `disable_all_ffw_hacks`

**AID / send:** `list_aid_keys`, `send_aid`, `send_attn`, `send_masked_keys`,
`send_field`, `send_fields`, `send_raw_hex`, `select_menu_option`,
`tamper_protected_field`

**Negotiation (escalation-gated):** `enable_ibmrseed_downgrade` /
`disable_…`, `get_captured_credentials`, `spoof_device_name`,
`clear_device_name_spoof`

**Mask injection:** `arm_mask_capture`, `get_mask_status`, `inject_word`,
`inject_wordlist`

**Compound:** `attempt_attn_escape`

**Tool-specific guardrails:**

- `enable_ibmrseed_downgrade`, `spoof_device_name` — Guardrail 5: human
  approval first.
- `inject_wordlist("cl-commands.txt")` — only after approval; this fires CL
  commands at the host.
- `send_fields` / `tamper_protected_field` — include the legit input field
  *and* the tamper field in one call. The host can't distinguish; that's the
  attack. Pad `value` to the field length — 5250 doesn't auto-clear, so a
  short value over a longer one leaves a tail (`"$0.01"` over `"$129.59"` →
  `"$0.01129.59"`).
- `send_aid("F5")` before `select_menu_option` — clears stale field content
  (single-char options don't fully overwrite multi-char leftovers).
